### Task 1: Playwright harness and the sign-in check

**Files:**
- Create: `frontend/playwright.config.ts`, `frontend/tsconfig.e2e.json`, `frontend/e2e/env.ts`, `frontend/e2e/signin.spec.ts`, `.github/workflows/e2e.yml`
- Modify: `frontend/package.json` (`@playwright/test` dev dependency at the current major, script `"e2e": "playwright test"`), `frontend/tsconfig.json` (reference `tsconfig.e2e.json`; ESLint's type-aware lint needs every linted file in a tsconfig), `frontend/.gitignore` (`playwright-report/`, `test-results/`), `AGENTS.md` (Frontend commands: `npm run e2e`, which needs `npm run build` first)

**Interfaces:**
- Consumes: `cd backend && uv run python -m tests.fakes.fake_openai --port N` (the fake's existing `main()`); `cd backend && uv run mlops-agents start --no-browser --port N` with `MLOPS_AGENTS_HOME` and `MLOPS_AGENTS_ACCESS_TOKEN` (api-foundation task 4); the UI built into `backend/src/mlops_agents/web/` by `npm run build`.
- Produces: `e2e/env.ts` exporting `APP_URL`, `FAKE_BASE_URL` (`http://127.0.0.1:<port>/v1`), `ACCESS_TOKEN`, `DATA_DIR`, used by every spec.

**Implementation notes:**
- `playwright.config.ts`: Chromium only; `webServer` is an array of two entries, so Playwright starts, waits for and stops both: the fake (ready on `<fake>/v1/models`) and the app (ready on `<app>/api/auth/status`), each with `reuseExistingServer: false` and a 60 s timeout. Ports are fixed constants in `env.ts` (8798 for the app, 8799 for the fake) so the config and the specs agree. The app's environment gets a fresh temporary `MLOPS_AGENTS_HOME` (created when the config loads, under the OS temp folder) and a random `MLOPS_AGENTS_ACCESS_TOKEN`; both go into `env.ts` through environment variables the config sets.
- The app runs from source (`uv run`), not from an installed wheel: installing is the packaging plan's install check; this plan tests the flow.
- `signin.spec.ts`: open `APP_URL/#token=<token>`; the shell shows the app name; the address bar has no `token`; reload: still signed in; open `APP_URL/` in a new context without the token: the local-mode sign-in page.
- `e2e.yml`: ubuntu-latest, on pull requests and pushes to `main`; Node 22 and uv; `npm ci`; `npx playwright install --with-deps chromium`; `npm run build` (UI into the backend); `cd backend && uv sync --locked`; `npm run e2e`; upload `playwright-report/` when it fails.

**Tests:** `signin.spec.ts` passes locally and in CI.

**Checks:** `npm run lint`, `npm run format:check`, `npm test`, `npm run build`, `npm run e2e`.

### Task 2: The stage 1 flow

**Files:**
- Create: `frontend/e2e/flow.spec.ts`, `frontend/e2e/repo.ts`

**Implementation notes:**
- `repo.ts`: in the spec's `beforeAll`, create a git repository in a temporary folder with `child_process.execFileSync("git", ...)` and `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL` set in the environment: a `README.md` whose first line is a known sentence and one Python file, committed on `main`.
- `flow.spec.ts` follows the overview's five steps, through the UI only, by role and label (no test ids, no API calls from the test):
  1. sign in with the token link (as task 1);
  2. "AI providers": add a self-hosted provider with `FAKE_BASE_URL`; add the model `fake-tools` from its list; verify it (wait for the verified state; verification is a real call to the fake); choose it as the Orchestrator's default model;
  3. "Projects" → "Add project" → "Local folder": type the repository's path in "Folder path", go, "Use this folder"; the project opens;
  4. "Agents": type "What does the README say?" in the message box and send; a tool step "Read" mentioning `README.md` appears; expanding it shows the file's first line; the answer streams in and contains the README's first line;
  5. reload: the conversation is still there, tool step included.
- Labels: use the pages' visible labels. When a page's label differs from the words above, use the page's. When a step cannot be done through the UI, that is a defect of the page's plan: open a Bug issue, do not work around it in the test.

**Tests:** `flow.spec.ts` passes locally and in CI, three runs in a row without a retry (`--repeat-each=3` once by hand; report it in the PR).

**Checks:** as task 1.
